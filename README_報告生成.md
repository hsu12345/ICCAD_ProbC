# 專題報告生成指南

本目錄提供了生成符合**清華大學資訊工程系專題報告格式要求**（經 20170511 課程委員會通過）的工具和說明。

| 檔案名稱 | 說明 |
|---------|------|
| `generate_report_template.py` | **自動生成 Word 模板的 Python 腳本** |
| `報告格式說明.md` | 詳細的格式要求和規範 |
| `報告模板範例.md` | Markdown 格式的內容結構範例 |

## 🚀 快速開始

### 方法一：使用 Python 自動生成模板（推薦）

#### 1. 安裝依賴

```bash
pip install python-docx
```

或使用依賴清單：
```bash
pip install -r requirements_report.txt
```

#### 2. 運行生成腳本

```bash
python generate_report_template.py
```

這會生成一個名為 `專題報告模板.docx` 的 Word 文檔，已根據**官方格式**配置好所有設定。

#### 3. 在 Word 中編輯

1. 打開生成的 `專題報告模板.docx`
2. 填入專題相關資訊（可參考 `ICCAD專題報告範例.md`）
3. **重要**：檢查並調整格式
   - 確保英文和數字部分使用 Times New Roman 12pt
   - 添加頁碼（插入 > 頁碼 > 頁面底端 > 置中）
   - 檢查標點符號是否為全型
   - 確認邊界設定正確

### 方法二：參考範例手動創建

1. 閱讀 `報告格式說明.md` 了解詳細格式要求
2. **參考 `ICCAD專題報告範例.md` 獲取完整內容結構**
3. 在 Microsoft Word 中按照格式要求創建文檔

## 格式要點提醒

### ✅ 必須檢查的項目

1. **紙張和邊界**
   - 紙張：A4 (21cm x 29.7cm)
   - 上邊界：2.54cm
   - 下邊界：2.54cm
   - 左邊界：3.17cm
   - 右邊界：3.17cm

2. **字體設定**
   - 中文：新細明體，12pt
   - 英文/數字：Times New Roman，12pt

3. **標點符號**
   - 使用全型標點符號（，。；：！？）

4. **頁碼**
   - 位置：頁面下方置中

5. **圖表**
   - 表格：表名在表格上方（表1、表2...）
   - 圖片：圖名在圖片下方（圖1、圖2...）

6. **參考文獻**
   - 中文在前，英文在後並依序編號

7. **重要限制**
   - 內容中不得揭露指導教授姓名

## 常見問題

### Q: Python 腳本無法運行？

**A:** 請確保已安裝 python-docx：
```bash
pip install python-docx
```

如果使用 Python 3，可能需要使用：
```bash
pip3 install python-docx
```

### Q: 生成的 Word 文檔格式不正確？

**A:** 由於 Word 格式的複雜性，生成的模板可能需要在 Word 中進行微調：
1. 檢查頁面設定是否正確
2. 手動設置英文和數字的字體為 Times New Roman
3. 手動添加頁碼
4. 檢查行距是否為單行間距

### Q: 如何在 Word 中批量替換字體？

**A:** 
1. 使用 Ctrl+H 開啟「尋找與取代」
2. 點擊「更多」>「格式」>「字體」
3. 設定要尋找和取代的格式
4. 執行取代

### Q: 標點符號如何確保為全型？

**A:**
1. 在輸入法中切換到全型模式
2. 或在完成後使用 Word 的「尋找與取代」功能：
   - 尋找半型標點符號（如 `,`、`.`）
   - 取代為全型標點符號（如 `，`、`。`）

## 建議的工作流程

1. **準備階段**
   - 閱讀 `報告格式說明.md` 了解格式要求
   - 閱讀 `報告模板範例.md` 了解內容結構

2. **模板生成**
   - 運行 Python 腳本生成 Word 模板
   - 或在 Word 中手動創建符合格式的文檔

3. **內容撰寫**
   - 根據專題實際情況填入各章節內容
   - 準備相關圖表並按照格式要求插入

4. **格式檢查**
   - 使用檢查清單逐一確認格式要求
   - 請同學或老師協助檢查

5. **最終確認**
   - 確認所有必要內容都已包含
   - 確認未揭露指導教授姓名
   - 確認格式完全符合要求

## 💡 ICCAD 2025 Problem C 專題建議

如果您的專題是參加 ICCAD 2025 Contest Problem C，可以參考以下建議：

### 內容建議

1. **專題研究動機與目的**
   - 說明增量佈局優化的重要性
   - 介紹 ICCAD 競賽問題
   - 闡述研究目標

2. **現有相關研究概況及比較**
   - DREAMPlace 系列方法

   - 時序驅動佈局技術

3. **設計原理**
   - 問題定義（TNS, WNS, HPWL）
   - 系統架構圖
   - 核心演算法說明

4. **研究方法與步驟**
   - 環境建置（Docker, DREAMPlace）
   - 開發流程
   - 實驗設計

5. **系統實現與實驗**
   - 使用工具列表
   - 測試案例結果
   - 效能比較表格

6. **專題重要貢獻**
   - 演算法創新點
   - 實作貢獻
   - 競賽成果

7. **團隊合作方式**
   - 分工說明
   - 協作工具（Git, Docker 等）
   - 遇到的挑戰與解決

8. **效能評估與成果**
   - 詳細實驗數據
   - 與基準方法比較
   - 視覺化結果

9. **結論**
   - 研究總結
   - 限制與展望
   - 學習心得

建議在報告中包含以下圖表：

1. **系統架構圖**：展示整體流程

3. **效能比較表**：各測試案例的結果

## 🆘 常見問題補充

### Q: 報告頁數有限制嗎？
**A:** 通常沒有嚴格限制，但建議控制在 20-40 頁之間。內容應完整但精簡，避免冗長。

### Q: 可以使用彩色圖片嗎？
**A:** 可以，但建議確保黑白列印時仍然清晰可讀。

### Q: 程式碼需要放在報告中嗎？
**A:** 重要的演算法可以用偽代碼展示，完整程式碼可以放在附錄或提供 GitHub 連結。

### Q: 實驗數據不理想怎麼辦？
**A:** 誠實報告實驗結果，並在結論中分析原因和可能的改進方向。這也是專題報告的重要部分。

### Q: 可以參考去年的報告嗎？
**A:** 可以參考架構，但內容必須是自己的原創工作。直接抄襲會有學術誠信問題。
